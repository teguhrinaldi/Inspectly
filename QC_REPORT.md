# QC Report — Inspectly (Flutter + Laravel)

Tanggal audit: 2026-11-08 · Commit: `b28766a` ("snapshot sebelum qc") · Mode: **audit saja, tidak ada kode yang diubah**

> Catatan metode: semua perintah Laravel (composer install, route:list, test, pint, migrate:fresh --seed, Larastan) dijalankan pada **salinan** `BE/` di folder temp, agar `composer install` (yang memicu `filament:upgrade` / publish asset) dan `migrate:fresh` tidak menyentuh repo maupun database MySQL lokal. Perintah Flutter dijalankan langsung di `app/` (read-only kecuali `.dart_tool`/`build`).
> Temuan layout yang ditandai **(est.)** dihitung manual dari token tema (lebar teks/tombol) — perlu dikonfirmasi dengan golden test atau device 360dp.

## 1. Pemetaan proyek

### Struktur
```
inspectly/
├── app/                Flutter (inspector app; Demo Mode default, API Mode via --dart-define)
│   ├── lib/app/        router (go_router), shell (bottom-nav phone / sidebar tablet), theme, providers (Riverpod)
│   ├── lib/core/       network (Dio ApiClient), storage (secure token), errors, utils, widgets
│   ├── lib/data/       models (freezed/json_serializable), repositories (interface + mock + api), services (pdf, kamera, GPS, notifikasi), demo datasource
│   ├── lib/features/   auth, dashboard, inspections, create, checklist, findings, reports, qr_scanner, profile
│   └── test/           4 file test (18 test)
├── BE/                 Laravel 10 REST API (Sanctum) + Filament 3 admin panel
│   ├── app/Http/       12 API controller, 16 FormRequest, 13 Resource, middleware `admin`
│   ├── app/Filament/   Dashboard, Reports, Settings + 5 Resource (Customer, Site, Inspector, Template, Inspection)
│   ├── database/       18 migration, 13 factory, DemoSeeder
│   └── tests/          9 file test (35 test)
├── docs/               architecture.md (kontrak API), api.md, deployment.md, dll.
└── marketing/          thumbnail + video
```
`_patch.dart` di root = file kosong 0 byte yang ter-commit (sampah).

### Fitur & alur utama
Login (atau Demo) → Home/Dashboard → scan QR site atau Create Inspection → Start (ambil GPS) → Checklist wizard (Pass/Fail/NA, catatan, foto per item, Fail → Finding + foto) → Findings/Evidence → Signature (inspector + customer) → Complete (hitung pass %, jadwalkan recurrence) → Report PDF (dibuat di device) / Risk Summary / Comparison dengan inspeksi sebelumnya. Admin bekerja di Filament (`/admin`).

### Screen Flutter (route)
`/welcome`, `/login`, `/home` (Dashboard / TabletHome), `/inspections`, `/inspections/:id` (Detail + tab Notes), `…/findings`, `…/evidence`, `…/signature`, `…/summary` (Risk Summary), `…/comparison`, `/create`, `/reports`, `/report/:id` (PDF preview), `/checklist/:id`, `/qr-scanner`, `/profile`.

### Route API Laravel (`/api`, 36 route; total 67 termasuk Filament/web)
`POST login` · auth:sanctum → `POST logout`, `GET me`, `GET|POST inspections`, `GET|PUT inspections/{id}`, `POST inspections/{id}/start|complete`, `PUT inspections/{id}/items/{item}`, `GET inspection-templates(/{id})` + admin `POST|PUT|DELETE`, `GET customers(/{id})` + admin `POST|PUT`, `GET|POST sites`, `GET|PUT sites/{id}`, `GET sites/{id}/history|comparison`, `GET inspectors` + admin `POST|PUT`, `POST findings`, `PUT findings/{id}`, `POST evidence`, `DELETE evidence/{id}`, `POST signatures`, `GET reports/{id}`, `GET activities`.

## 4. Yang sudah diperiksa dan dinilai baik
- **Mass assignment:** semua model memakai `$fillable` eksplisit, controller memakai `$request->validated()`; `User` men-`hidden` password/remember_token. `role` ada di fillable tetapi tidak pernah diisi dari input request API.
- **SQL injection:** tidak ada `DB::raw/whereRaw/selectRaw`; pencarian memakai binding `like`.
- **Upload file:** evidence & signature divalidasi `file|image|max` (10MB / 5MB), disimpan dengan nama acak di disk `public`.
- **Route admin:** write template/customer/inspector di balik middleware `admin` (ber-test); panel Filament dibatasi `canAccessPanel()` (admin + active).
- **Eager loading API:** `InspectionController` / `ReportController` / `SiteController` memuat relasi secara eager — tidak ditemukan N+1 di endpoint API.
- **Migration & seeder:** `migrate:fresh --seed` berhasil dari nol (SQLite, dua kali berturut-turut).
- **Kontrak umum:** nama field snake_case cocok (`field_rename: snake`), enum ber-`@JsonValue` cocok dengan nilai server, ID integer dinormalisasi ke string (`normalizeIds`, ber-test), tanggal ISO-8601 UTC dari Laravel ter-parse oleh `DateTime.parse`, `pass_percentage` int→double aman, envelope `{data}` ditangani `unwrap()`.
- **Token storage:** Sanctum token di `flutter_secure_storage`, bukan SharedPreferences.
- **Controller dispose:** semua TextEditingController, SignatureController, MobileScannerController di-dispose; tidak ada Timer/Stream yang bocor.
- **Keyboard di sheet finding:** `isScrollControlled` + `viewInsets` + `DraggableScrollableSheet` benar.
- **Manifest/Info.plist:** INTERNET, CAMERA, lokasi foreground, POST_NOTIFICATIONS, usage description iOS lengkap; tidak ada background location.
- **Flutter analyze bersih, format bersih (lib/test/tool), 18/18 test lulus.**

## 5. Ringkasan

Kode Flutter tergolong rapi: analyzer dan format bersih, semua test lulus, dan arsitektur repository Demo/API jelas. Masalah terbesar justru ada di **jalur API Mode dan backend**, yaitu jalur yang belum pernah diuji sebagai produk produksi:

1. **Keamanan backend belum siap produksi.** Tidak ada otorisasi per data (QC-001). Framework Laravel 10 sudah EOL dengan 15 advisory dan dependency tidak lagi bisa di-resolve (QC-002). Token tidak pernah kedaluwarsa, dan inspector yang dinonaktifkan atau dihapus tetap punya akses (QC-003/004).
2. **Kontrak API rapuh terhadap data nyata.** Satu field null membuat seluruh daftar gagal dimuat (QC-005). Pagination diabaikan sehingga site ke-16 dan seterusnya tidak bisa di-scan (QC-006). `complete` tidak idempoten (QC-007).
3. **Sesi & error handling di Flutter.** Tidak ada logout otomatis saat 401. Saat offline user terlempar keluar. Cache data bocor antar user. Pesan error berbunyi "Instance of …". Banyak screen tidak punya tombol retry (QC-008 sampai QC-011).
4. **Risiko kehilangan data lapangan.** Foto gagal upload tanpa pesan, catatan checklist hilang saat menekan back, dan PDF gagal total bila satu file hilang (QC-012/013/016).
5. **Rilis Android.** APK masih memakai debug signing, receiver notifikasi belum dideklarasikan, dan permission media berisiko ditolak Play (QC-015/019/048).
6. **Demo story backend bergantung pada tanggal.** Akibatnya test admin dashboard gagal hari ini dan angka dashboard tidak lagi cocok dengan mockup (QC-020).

**Rekomendasi: belum layak rilis produksi** sampai seluruh Critical dan High ditutup.
